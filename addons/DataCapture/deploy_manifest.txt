# DataCapture deploy manifest: the ONLY files tools/deploy_addon.py may copy into the deployed addon
# (<DATA_ROOT>/addons/DataCapture, DATA_ROOT of the local config, DD-22). Review every change to this file.
#
# Format: one entry per line, "<kind> <repo-relative source path>". '#' starts a comment.
#   addon   a Workbench resource under addons/DataCapture/ (.gproj .ent .layer .et .conf),
#           deployed to the same path relative to the addon root
#   script  an Enforce script at the top level of src/enfusion/datacapture/,
#           deployed to Scripts/Game/DataCapture/
#   config  a .json file under addons/DataCapture/Configs/ (deployed to the same path, e.g. Configs/routes/), or a
#           vehicle card tools/ident/cards/<pin_id>/<id>.json (deployed to Configs/ident/cards/<pin_id>/<id>.json);
#           copied byte for byte (llc_v1 and the expert hash what they load)
#
# The tool refuses these even if they are listed here:
#   - core/, modules/ and every other subfolder of src/enfusion/datacapture/
#   - DriveDiT_DataCapture/ (the unloadable in-repo prototype addon) and src/SCR_CaptureTests.c
#   - the auxiliary prototypes SCR_BinarySerializer, SCR_DepthRaycaster, SCR_DrivingSimDebugUI,
#     SCR_ModularCaptureExample, SCR_MultiCameraRig, SCR_SceneEnumerator
#   - SCR_AIDrivingSimulator (superseded by the compiled director; must never run next to it)
#   - Workbench-generated files (*.meta, resourceDatabase.rdb, UserMaps.desc)
# Scripts/Game/DataCapture/DC_BuildInfo.c is generated by the tool on every deploy (build stamp).
